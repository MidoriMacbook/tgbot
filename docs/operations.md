# Эксплуатация

Запуск: `python run.py`. Launcher поднимает сайт на Waitress, polling бота и доставку уведомлений в одном контейнере, контролирует завершение процессов и останавливает их вместе. Все используют один DATABASE_PATH. После перезапуска сохраняются заявки, история, незавершённые диалоги и очередь сообщений. Должен работать только один runbot на токен; Telegram webhook для polling должен быть отключён. Если бот использовался с webhook, отключите его методом deleteWebhook без удаления ожидающих обновлений; токен не вставляйте в команды, попадающие в общедоступные журналы.

`.env` автоматически загружается Python из корня проекта, его содержимое не выполняется как код. Переменные окружения контейнера имеют приоритет. PowerShell-обёртка `scripts/start.ps1` без аргумента тоже запускает весь проект. При смене пути БД перезапустите launcher. Настройка `pur3.me` описана в [инструкции размещения](hosting.md).

## Доставка

```powershell
. ./scripts/env.ps1
.venv/Scripts/python.exe manage.py delivery_status
.venv/Scripts/python.exe manage.py notify --once
.venv/Scripts/python.exe manage.py notify --interval 2
```

Смена статуса и запись задания атомарны. При штатном локальном запуске очередь проверяется раз в 2 секунды. Каждый запрос Telegram ограничен 10 секундами; длинный текст делится на части. После временного сбоя повтор через 2, 4, 8, 16, затем 30 секунд; ограничение Telegram retry_after учитывается и может быть дольше. Аренда задания на 30 секунд не допускает одновременной отправки двумя процессами; транзакция во время сетевого запроса не удерживается. Более поздний статус одной заявки ждёт доставки предыдущего. У других заявок доставка продолжается.

После аварии процесса задание становится доступно по истечении аренды. Гарантия at-least-once: после отправки и аварии до записи результата возможен дубль; при частичной отправке длинного сообщения повторяется всё сообщение. Успешные и неуспешные попытки хранятся в Notification (включая attempts, last_error, sent_at, next_attempt), безопасная сводка доступна delivery_status. Polling сохраняет курсор принятых обновлений и состояние диалога; если ответ потерян при недоступной сети, повторите сообщение, «Подтвердить» или запрос статуса — повторная заявка не создаётся.

Для минутного срока должны быть доступны Telegram API, чат заявителя и свободная очередь. Блокировка бота заявителем, 429, разрыв сети, длительная остановка процесса или очередь свыше пропускной способности не дают гарантии 60 секунд. Ошибки фиксируются без токенов. Внешние сбои не теряют задания. Отдельного архива попыток нет: сохраняются счётчик и последняя ошибка каждого задания. Невозможная доставка (например, заявитель заблокировал бота) остаётся в очереди до вмешательства администратора.

## Оформление бота

Входящие данные, сохранённые заявки и задания Notification хранятся обычным текстом. HTML формируется при отправке: пользовательский текст экранируется, длинные сообщения разбиваются с сохранением тегов и учётом UTF-16. Поэтому задания, созданные до обновления оформления, продолжают доставляться без миграции данных.

Навигация использует inline-кнопки и редактирует текущее сообщение. Новый ответ отправляется при вводе текста, уведомлении или невозможности редактирования; ответ Telegram «message is not modified» не создаёт дубль. Нижнее постоянное меню показывает цветные кнопки с разными иконками. Подписи, цвета, набор иконок, таймауты и переключатели находятся в `.env`. Выбор категории привязан к её ID. После изменения данных прежняя кнопка подтверждения устаревает; повтор выполненного подтверждения не создаёт ещё одну заявку. `/start`, `/status` и прежний текстовый сценарий поддерживаются.

Premium-иконки взяты из предоставленного пользователем визуального референса. Проверены только идентификаторы и тип эмодзи через read-only Telegram API. Разрешение на их отправку зависит от Telegram Premium владельца бота или дополнительного имени через Fragment. Если API отклонит custom emoji, сначала убираются иконки кнопок, затем custom emoji в тексте заменяются обычными; HTML, цвет и действия кнопок сохраняются. Иные ошибки Telegram не скрываются и обрабатываются существующим механизмом повторов. Для отключения Premium задайте `TELEGRAM_CUSTOM_EMOJI=0` и перезапустите процессы.

Цветные кнопки используют только поддерживаемые Telegram стили: primary, success, danger. Произвольный цвет текста или фона обычного сообщения API не задаёт. Официальные правила: [KeyboardButton](https://core.telegram.org/bots/api#keyboardbutton), [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton), [HTML](https://core.telegram.org/bots/api#html-style).

## Резервная копия и обновление

Для локальной демонстрации остановите все три процесса и скопируйте файл из DATABASE_PATH в защищённое место вне Git. Копируйте `.env` отдельно и с ограниченными правами. Для восстановления остановите процессы, верните БД и настройки, примените миграции, запустите компоненты. Не копируйте активную SQLite простым файловым копированием во время записи.

Обновление: сохраните локальные изменения, получите коммиты Git, установите requirements.lock, сделайте резервную копию, выполните `manage.py migrate` и `manage.py check`. Пароль администратора можно сменить через `manage.py changepassword ИМЯ`.

Публичной регистрации и автоматического сброса пароля нет. Главный оператор создаёт доступы в `/team/`, пароль показывается однократно. Обычный администратор не может выдавать администраторские права и управлять главным оператором. Публичный HTTPS может обслуживаться прокси без сертификата в контейнере; см. [размещение](hosting.md). SQLite сериализует писателей; прежние нагрузочные показатели относятся к исходному прототипу.
