# План обновления оформления

Цель: выполнить заданный пользователем редизайн веба и бота без потери функций ТЗ.
Спецификация: docs/specs/2026-11-05-soft-glass-design.md.
Ветка: prototype; рабочие данные и секреты вне Git.

## Общие ограничения

Сохранить Django, aiogram, существующие маршруты, роли и операции. Русские тексты. Только реально поддерживаемые Telegram API возможности. Веб и бот меняются независимо, без общих редактируемых файлов.

## Задачи

- [x] 1. Веб: app/web/templates/**, app/web/static/**, при необходимости app/web/forms.py и views.py, tests/test_web.py. Реализовать soft/glass оформление всей панели и админки, мобильные карточки, доступность и состояния. Изменения поведения сначала закрепить падающим тестом. Проверить веб-тесты, серверный HTML и адаптивные правила; интерактивная визуальная проверка отменена по прямому указанию пользователя.
- [x] 2. Бот: app/bot/**, tests/test_bot.py, tests/test_bot_presentation.py, при необходимости настройки и .env.example. Сначала тесты HTML/экранирования/разбиения/стилей и деградации Premium, затем реализация. Сохранить plain-text outbox и статус владельца. Проверить tests.test_bot, tests.test_bot_presentation, tests.test_notifications.
- [x] 3. Проверка и сдача: полный manage.py test tests --noinput (52 теста), check, makemigrations --check --dry-run, pip check; проверка HTML/CSS и референса, независимое ревью бота и авторское ревью веба; обновить документы, состояние, опубликовать проверенные коммиты от пользователя. Ограничения проверки отражены в docs/design-verification.md.

## Контрольные сценарии

Длинные кириллические тексты и emoji, спецсимволы HTML в контакте и описании, недоступный custom emoji, старые черновики, старые plain-text уведомления, пустые/ошибочные формы, клавиатурный доступ и мобильное переполнение.
