# Решения проекта

## 2026-11-05 [saved]

Цель: воспроизводимый прототип приёма и обработки заявок.

Решения:
- Django объединяет ORM, миграции, сессии и справочники, сокращая инфраструктуру локальной демонстрации.
- SQLite IMMEDIATE обеспечивает атомарную историю и единственного победителя конкурентного взятия.
- Уведомления хранятся в БД с арендой и порядком внутри заявки; возможны повторы после аварии.
- Отключение сотрудников и справочников сохраняет историю; категория и автор фиксируются снимками.
- Ветка prototype использует нейтральное имя по указанию пользователя.

Отклонено: оценивать полный цикл скоростью SQL; хранить секреты в Git.

Живой обмен выполнен 5 ноября 2026 года: уведомления и запрос статуса подтверждены заявителем. Токен и контакты в Git не сохраняются.

## 2026-11-05 [saved] оформление

Цель: мягкая стеклянная веб-панель и оформление бота по визуальному референсу пользователя.

Решения:
- Светлая мятная палитра сочетает мягкие тени и ограниченное размытие; контраст важнее слабых границ Neumorphism.
- HTML формируется при отправке; старые plain-text задания очереди остаются совместимыми.
- Inline-кнопки используют ID и nonce представления; изменённые данные требуют нового подтверждения.
- Иконки взяты из предоставленного архива; недоступный Premium заменяется обычными эмодзи без потери действий.

Отклонено: перенос настроек референса; произвольные цвета сообщений, не поддержанные Telegram API.

Открыто: ручная визуальная приёмка; пользователь запретил дальнейшее управление компьютером.
